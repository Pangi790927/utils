# examples

Real cases, kept because they happened, not because they can be reused.

An example is a specific thing that was actually written, with the reasoning that produced it and
the wrong turns that came before. It is read to see how a rule behaves under load. It is not filled
in, not copied into a project, and it usually names files and symbols that exist in exactly one
repo - that specificity is the point, and it is what separates this directory from `templates/`.

Anything here that turns out to be generally useful has stopped being an example. Generalise it
into `templates/`, or fold the lesson into the skill it belongs to, and leave the example behind as
the record of where the rule came from.
